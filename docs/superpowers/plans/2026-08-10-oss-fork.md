# OSS fork implementation plan — Phases 0 → 2

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:test-driven-development
> and superpowers:systematic-debugging while implementing. Steps use checkbox
> (`- [ ]`) syntax for tracking.

**Goal:** Take this repo from its current state to the point where the control
loop is a tested program with a pluggable backend, running behavior-identically
to today. This covers Phases 0–2 of
`docs/superpowers/specs/2026-08-10-oss-fork-design.md`. Phases 3–5 (second
backend, cutting the public repo, launch polish) get their own plan once Phase 2's
gate is green.

**Architecture:** Phase 0 lands the in-flight domain-packs work. Phase 1 removes
the three things that only work on this machine. Phase 2 splits the ~730-line
`delegate-to-pi/SKILL.md` into *judgment* (prose the orchestrator follows) and
*mechanism* (`bin/crew`, a tested CLI enforcing spawn/reuse, settle detection,
caps, ledger, fallback, telemetry), behind a five-verb backend adapter contract.

**Tech stack:** Bash + Python 3, `jq`, `rg` — matching `bin/` and
`lib/telemetry/`. No new runtime dependencies.

## Global constraints

- **Never implement directly.** Every step below is delegated to a `pi` worker
  via `delegate-to-pi` launched through `./bin/pi-project` (`CLAUDE.md` rule 1).
  Claude Code plans, resolves conflicts of judgment, verifies, and integrates.
- **Behavior preservation is the gate that matters.** Phases 0 and 2 both end
  with real `S`-tier and `M`-tier delegations, not just green greps. The existing
  tests assert on literal strings inside `SKILL.md`; they can stay green while
  the skill has actually drifted.
- **Authority boundary is absolute** and survives every refactor: crew members
  get no outward-facing tool, ever.
- **Fail-loud discipline** extends to every new lookup (`POLICY.md`, profile
  resolution, adapter selection): missing or malformed input stops the run and
  names the exact defect. Never fall back, never improvise.
- `.factory/`, `.superpowers/`, `.worktrees/`, `.projects/`, `var/telemetry/`
  stay gitignored. `var/telemetry/events.jsonl` records **verbatim user prompts**
  and never leaves this machine.
- No push, PR, merge to a shared remote, or branch deletion without the human's
  Checkpoint 3 approval.

## Decisions taken (not open questions)

1. **Merge direction for Phase 0:** rebase `feat/domain-packs` onto `main`, not
   merge `main` into it. The conflict is in one file and a rebase keeps the 15
   domain-pack commits readable as their own story in the history that will
   later be extracted publicly.
2. **Conflict resolution authority:** the SKILL.md conflict is resolved by a
   `pi` worker under `L`-tier review, but Claude Code reads the merged §1–§12 in
   full before the gate — this file is the product, and a silent regression in it
   is the single highest-consequence failure available in this repo.
3. **Role name rename is deferred to Phase 2, and is deliberate.**
   `pi-isolated-<role>-<TIER>` becomes `crew-<role>-<TIER>` only when the skill
   stops being pi-specific. This invalidates reuse of any agent running under the
   old name — acceptable at this version boundary, but it must be stated in the
   Phase 2 report, not discovered.
4. **`delegate-to-pi` survives as a thin alias** to the renamed `orchestrate`
   skill, exactly as `autonomous-build` now aliases `autonomous-goal`. Muscle
   memory and `CLAUDE.md` keep working.
5. **`bin/crew` owns state; prose owns judgment.** Anything the model must
   *decide* stays prose. Anything that must be *true regardless of the model*
   becomes a program that exits non-zero.
6. **Phase 2 runs at `M`.** *(Revised 2026-08-10; this decision previously
   said `L`.)* The architecture-level judgment in Phase 2 lives in 2a's
   contract spec, which the orchestrator writes and never delegates. Once
   that spec exists, each delegation is transcription against a precise
   contract — multi-file coordination with a clear spec, which is the `M`
   rubric, not the `L` one. Nothing in Phase 2 meets `L`'s bar of
   architecture-level judgment *by the worker*, ambiguous scope, or a
   security-sensitive surface.

   Evidence from Phase 0 and Phase 1: seven delegations ran at `S`/`M`,
   including the `SKILL.md` merge conflict — the highest-consequence change
   available in this repo — which converged in one round. Every genuine
   failure in those phases was an **orchestrator spec error** (a
   self-contradictory fail-loud instruction, an unsatisfiable acceptance
   criterion, an under-specified test isolation), not a worker capability
   limit. A higher tier does not fix an ambiguous brief; it produces a more
   convincing implementation of the wrong thing.

   The quality mechanisms are spec precision, the mechanical oracle, the
   independent reviewer, and clean-checkout verification — none of which is
   tier-dependent. The `L` confirmation gate is a **cost control**, not a
   quality mechanism, and should not be spent as if it were one.

## Phase 1 — Portability surgery

Three things currently work only because of this machine. Each is a defect in
the private repo too, so all three land on `main` before any extraction.

### 1a. `POLICY.md` — the risk gate currently has no portable content

`delegate-to-pi` §5 and `autonomous-goal`'s Checkpoint 2 both defer to "the
user's global CLAUDE.md Never/Off-limits rules". A cloner has no such file, so
the gate silently matches nothing.

- [ ] Write `POLICY.md` at the repo root: destructive git/filesystem operations,
      secrets and credential stores, production systems and live customer data,
      and any outward-facing send/publish/pay action.
- [ ] State the precedence rule in it: a local overlay (`POLICY.local.md`,
      gitignored) and a domain pack's risk gate may **add** prohibitions; neither
      may weaken one. Domain packs already specify "in addition to, never instead
      of" — this makes that enforceable from one place.
- [ ] Repoint `delegate-to-pi` §5 and `autonomous-goal` Checkpoint 2 at
      `POLICY.md`.
- [ ] Add `tests/test-policy.sh`: `POLICY.md` exists and carries all five
      categories; no skill file still defers to "global CLAUDE.md" for the gate;
      the precedence rule is present.

### 1b. Profile table becomes example + local override

- [ ] Add `config/profiles.example.json` carrying the shape, with placeholder
      provider/model values.
- [ ] Implement resolution order in `delegate-to-pi` §1:
      `config/profiles.local.json` → `config/profiles.json` →
      `.claude/skills/delegate-to-pi/references/pi-profiles.json` (current path,
      kept working). Unchanged fail-loud behavior when none parses or a tier is
      missing.
- [ ] Gitignore `config/profiles.local.json`.
- [ ] Extend the profile tests to cover the resolution order and the
      all-sources-missing failure message.

### 1c. Ledger path, settings split, path scrub

- [ ] Move the crew ledger from the vendored superpowers namespace to
      `.factory/crew/<id>/`; update `SKILL.md`, `.gitignore`, and any test.
- [ ] Split `.claude/settings.json` into a shippable minimum (the four telemetry
      hooks) plus `.claude/settings.local.json` (gitignored) holding
      `enabledPlugins` and `skillOverrides`.
- [ ] Remove every absolute home-directory path from tracked files.
- [ ] Add `tests/test-portability.sh`: no tracked file contains a
      home-directory path; no tracked file references the old vendored ledger namespace.

### 1d. Telemetry sink must be explicit, not cwd-derived

**Found live during the first real research delegation (2026-08-10).**
`bin/telemetry-record` and `.claude/hooks/telemetry-log.sh` both anchor the
log to `$(git rev-parse --git-common-dir)`. From a *linked worktree* of this
repo that correctly resolves to the shared checkout — which is what commits
`2431422` and `4111aee` fixed. But from a delegation whose cwd is an
**independent project repo** under `.projects/`, it resolves to *that* repo,
so telemetry silently fragments into the delegated workspace.

Observed impact: three `pi_spawn` records for the research delegation landed
in `.projects/research-self-improving-agents/var/telemetry/events.jsonl`
instead of the factory log, and a `git add -A` in that workspace then
**committed them into the project repo**. In that instance the records held
no prompts, but the `UserPromptSubmit` branch of the hook writes verbatim
user prompts, so the same mechanism in a longer-lived workspace commits
prompt text into a repo intended to be shareable.

- [ ] Resolve the sink explicitly: `TELEMETRY_LOG_DIR` if set, else the
      factory repo root discovered from the script's own location — never
      from the caller's cwd.
- [ ] Add `tests/test-telemetry-sink.sh`: recording from a cwd inside an
      unrelated git repo still writes to the factory log and creates no
      `var/` in that repo.
- [ ] Ship `var/` in the workspace-scaffold `.gitignore` so a stray sink can
      never be committed by a project repo.

**Gate:** full suite green including the three new tests; one real `M`-tier
software delegation still completes unchanged.

## Phase 2 — Extract the mechanism (`bin/crew`)

The largest and highest-risk phase. Do not start it until Phase 1's gate is green.

### 2a. Define the contracts (no behavior change yet)

- [ ] Write `docs/specs/crew-contract.md` fixing the **Turn Contract** —
      every backend maps its native signals onto exactly `settled`, `blocked`,
      `failed`, `timeout` — and the adapter verbs:

      ```
      crew_capabilities   -> {layout, focus, persistent_context, native_status, banner, isolation}
      crew_list           -> [{id, name, cwd, status}]
      crew_spawn NAME CWD [--stack-under ID] -- ARGV...   -> {id}
      crew_status ID      -> settled|working|blocked|failed|unknown
      crew_send ID        (text on stdin)
      crew_read ID [--recent|--visible] [--lines N]
      crew_close ID
      crew_verify_profile ID PROVIDER MODEL THINKING      (exit 0/1)
      ```

- [ ] Specify the state file `.factory/crew/<DELEGATION_ID>/state.json`:
      delegation id, tier, domain, round, per-role `fallback_used`, per-role
      agent ids, and the last two diff hashes (for no-progress detection). This
      replaces the prose "re-read the ledger after compaction" instruction with
      something machine-readable.

### 2b. Implement `lib/crew/` + `bin/crew`

- [ ] `bin/crew spawn|send|wait|read|close|fallback|round|ledger|state`, backed
      by `lib/crew/`. Behavior copied verbatim from today's `SKILL.md`:
      reuse-by-role+tier+cwd, never reuse an unnamed agent, poll to settlement,
      profile verification after spawn, rate-limit signature detection,
      fallback once per role, round/turn caps, ledger append, telemetry emission
      including `domain=`.
- [ ] `crew round end --verdict ...` **exits non-zero at the cap** with an
      escalation payload, so the cap is enforced rather than instructed.
- [ ] No-progress detection compares diff hashes from the state file across
      consecutive rounds.

### 2c. Adapters

- [ ] `adapters/mux/herdr.sh` — today's behavior verbatim, including the
      focus → split-down → refocus stacking sequence and its documented gotchas.
- [ ] `adapters/worker/pi.sh` — generalizes `bin/pi-project`, declaring
      `isolation: true` and its status-bar banner regex.
- [ ] `adapters/mux/mock.sh` — replays scripted turn outcomes from a fixture
      file. This is what makes the loop testable with **no agent and no
      multiplexer installed**, and it is a deliverable, not a test helper.
- [ ] Backend selection via `FACTORY_MUX` / `FACTORY_WORKER`, defaulting to
      `herdr` / `pi`. Unknown or missing adapter → fail loud.
- [ ] An adapter that cannot restrict the worker to repo-local skills declares
      `isolation: false`, and `bin/crew spawn` warns loudly — without isolation,
      results stop being reproducible across machines.

### 2d. Tests (written before the implementation)

- [ ] `tests/test-crew-caps.py` — round 6 refused; turn cap at 6 for `S`.
- [ ] `tests/test-crew-no-progress.py` — two consecutive identical diff hashes
      stop the loop.
- [ ] `tests/test-crew-fallback.py` — fallback fires once per role; a second
      failure for the same role escalates; a different role is unaffected.
- [ ] `tests/test-crew-reuse.py` — never reuses another tier's agent, never
      reuses an unnamed agent.
- [ ] `tests/test-crew-state.py` — state survives an interrupted round;
      `crew state` reports the correct round.
- [ ] `tests/test-crew-telemetry.py` — the six event types emit with `domain=`.
- [ ] All of the above run against `adapters/mux/mock.sh` with no `pi` or
      `herdr` present.

### 2e. Rewrite the skill

- [ ] Create `.claude/skills/orchestrate/SKILL.md` calling `bin/crew`, keeping
      as prose exactly: tier and domain classification, prompt composition,
      diff/artifact judgment, `blocked`-question escalation calls, scout
      decisions, acceptance spec and test plan authoring, and the final report.
      **Target: under 250 lines.**
- [ ] Rename crew agents `pi-isolated-<role>-<TIER>` → `crew-<role>-<TIER>`;
      update `tests/test-delegate-to-pi-isolation.sh`.
- [ ] Reduce `delegate-to-pi/SKILL.md` to a thin alias pinning the `pi` + `herdr`
      backend and pointing at `orchestrate`.
- [ ] Repoint `autonomous-goal` Step 3 at `orchestrate`.

**Gate — behavior preservation:** the same real `S`-tier and `M`-tier software
goals from Phase 0 produce indistinguishable panes, ledger, round counts,
telemetry and report; the research goal still completes; the full suite is green
including the new `bin/crew` tests, and those tests pass on a machine with
neither `pi` nor `herdr` installed.

## Risks

| Risk | Mitigation |
|---|---|
| **Highest — silent drift in the merged `SKILL.md`.** Phase 0's conflict sits in a 730-line procedural file whose tests assert on literal strings; they can stay green while behavior changes | Claude Code reads the merged skill in full against both parents, and the gate requires three real end-to-end delegations, not greps |
| **Phase 2 reimplements a working loop.** Every rule transcribed from prose to code is a chance to lose a hard-won detail (settle-mode variance, `pane_id` vs name, the stacking sequence) | Copy verbatim, one rule per commit; the mock-adapter tests encode each rule as it moves; the gate is indistinguishability, not "looks right" |
| **Role rename breaks reuse** of any agent running under the old name | Stated in decision 3 and reported at the Phase 2 gate; agents are cheap to respawn |
| **`bin/crew` over-reaches** and starts making judgment calls, degrading the orchestrator to a shell script | The 2a contract is the arbiter: if a step needs a good model, it stays prose. Review each `bin/crew` subcommand against that test |
| **Phase 2 exceeds one delegation's round budget** | It is scoped as three delegations (2a+2b, 2c+2d, 2e), each with its own gate; escalate per §8 rather than expanding scope |
| **Research goal (Phase 0) needs live network retrieval** and may hit paywalls or ToS limits, which are risk-gate items | That is the pack working as designed; escalate to the human rather than routing around it |
